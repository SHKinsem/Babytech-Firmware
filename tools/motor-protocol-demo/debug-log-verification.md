# 日志、清状态及直接编排（2026-09-22）

用户最终要求：编排是按序发送指令的工具，执行边界由用户决定，不追加状态监督。此前队列等待 ACK、到位、停稳、配置读回的设计被本轮要求覆盖。

## 实现

- 顶部“清除板端状态”：POST `/api/control/reset`，取消队列和 UART 待执行事务，尝试停止并清除易失控制状态。保留配置、草稿、日志和 UART 去重结果；不自动使能或重跑。
- 成功仅表示软件状态清除及停止提交；停止发送失败返回 503 + `stateCleared:true`。网络超时表示未知，不自动重试。
- 修复从未收到反馈的 UI 选中地址导致广播停止后永久忙；过期/无归属的拒绝 ACK 不再重新挂起故障。
- 板端 `/api/logs`：48 条 RAM 环形事件，包含启动标识、状态变化及 HTTP 结果。网页本机历史支持筛选、Markdown/JSON 导出和刷新保留；保留观察到的控制 CAN 帧并记录缺口。不是串口全文，断电会丢板端环形记录。
- 编排按序直发，用户写 `wait` 才延时；旧格式 torque/velocity 的明确持续时间保留“计时后发送停止”的含义，省略持续时间则仅发送。结束仅表示发送结束，不是机械到位。
