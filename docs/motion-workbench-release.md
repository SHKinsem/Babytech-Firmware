# 电机协议工作台交付说明

> 历史切片：文中的 brain/脑板/上板指主控板 `main-controller`，motion/运动板/下板指设备板 `device-controller`。当前设备板默认连接外部显示板；与主控板联调须显式选择 `DEVICE_UART_PEER=1`。现行术语与兼容标识见[控制板命名](controller-naming.md)。下文保留当时的功能范围。

本版把 Claude Code 开发的桌面工作台接入 Motion 固件，整合原有 Wi-Fi 配网与电机控制。`device-controller/data/index.html` 是构建生成的单文件页面，CSS、JavaScript 均已内联，烧录后不依赖电脑网页服务、CDN 或单独文件系统分区。

目标硬件：ESP32-S3 N16R8，16 MB Flash、8 MB OPI PSRAM。CAN TX GPIO4、RX GPIO5，500 kbit/s；需要外接 CAN 收发器。UART brain 链路维持 GPIO43/44、115200。

## 本版可执行范围

| 功能 | 板端行为 |
| --- | --- |
| F3 / FE | 非同步使能、失能、立即停止；广播停止使用 ID 0 |
| CD | 相对当前位置模式 2，保留原有位置规划、ACK、反馈及超时监督 |
| F5 / C5 / F6 / C6 | 力矩、速度及限制变体；非同步，最多 5 秒试验，反馈过期提前停止 |
| 1F / 20 / 21 / 24 / 27 / 31 / 33 / 35 / 36 / 37 / 3A / 3B / 42 / 43 | 实际发送查询；未定义的返回格式保留原始 RX，不伪造解码 |
| 0A / 0E / 46 / 93 / 11 / 4C | 清零、清堵转、控制模式、原点设定、主动反馈与回零参数；需要驱动关闭使能、新鲜静止及驱动状态反馈 |
| 9C | 回零中断，并提交立即停止 |
| FF、同步队列、FB/CB、FD、9A、未知功能码 | 保留编辑与帧预览，板端拒绝执行；尚无对应可靠运动监督 |

CD 范围：角度绝对值 0.1–3600°，速度 0.1–120 RPM，加减速度整数 1–240 RPM/s，电流 100–5000 mA，预计时长 ≤60 秒。默认试动为 10°、10 RPM、300 mA。

速度试验：速度字 ≤1200（0.1 RPM），加速度 1–240，C6 电流 100–5000 mA。力矩电流 ≤5000 mA，C5 的 maxSpeed 协议字段限于 0–1200；不推断其物理单位。主动反馈间隔为 0 或至少 30 ms。回零参数速度字 ≤1200、超时 ≤60000 ms、堵转电流 ≤5000 mA，并拒绝上电自动回零。配置的模式字仍按协议字段展示，不猜测其取值语义。

基础 F5/F6 不含限速／限流字段，它们不会自动获得 C 系列保护能力；板端时间监督并不替代驱动器自身限制。5 秒试验结束后必须重新使能，才能发起下一次运动。

## 页面与网络

1. 连接热点 `Babytech-Motion`，密码 `babytech-demo`，访问 `http://192.168.4.1/`。
2. 在「常规试动」或「指令实验室」选择十进制 CAN ID 1–255，等待真实反馈，再显式使能。
3. 「Wi-Fi 设置」支持扫描／手动填写 SSID、保存并连接、显示 STA 地址、忘记已保存网络。热点始终保留；连接和扫描可能因单无线电切换频道暂时中断网页。
4. Wi-Fi 扫描、连接、忘记与自动重连均避让受控电机使能／运动／待停止状态。先停止、等待反馈，再发送失能，才能修改网络。

页面 HTTP 断线后清空显示读数，不自动重发操作。HTTP 202 仅表示提交成功，不能视为电机执行或运动完成。CD 的完成仍由 ACK 加两对新的到位／静止反馈确认。切换页面或关闭浏览器不撤销已接受的有界运动；停止由板端时间和反馈监督负责，也可点击「全部停止」。

收发记录来自真实驱动：TX 是成功进入 TWAI 队列，RX 是实际收到的帧。板端环形缓冲 48 帧、网页保留 400 条，旧记录可能覆盖；非完整总线抓包。自动查询同样出现在记录中。底层多包命令失败后不会报告成功。

## 新增接口

- `POST /api/command`：表单 `hex`，3–30 字节的连续十六进制串。地址、功能码、常量、长度、同步及参数范围均由板端再次校验，不能利用 HEX 编辑器绕过运动门限。
- `GET /api/trace`：`uptimeMs`、`sequence`、`frames`。每帧包括 `seq/atMs/dir/id/extended/remote/data`。
- 原有 `/api/status`、`/api/enable`、`/api/move`、`/api/stop`、`/api/stop-all`、`/api/can-debug` 和 `/api/wifi*` 保持可用。`activeId` 包含当前速度／力矩试验目标，状态新增 `experiment_running`。

## 重建

在 `tools/motor-protocol-demo` 执行 `npm ci`（首次），随后 `npm run build:device`。该步骤覆盖生成的 `device-controller/data/index.html`，不要手工编辑生成文件。

回到仓库根目录执行：

```powershell
./tools/build-wsl.ps1 -Target motion
```

也可使用已安装的原生 PlatformIO：`pio run -d device-controller`。前端未修改时，直接编译已提交的内嵌 HTML 即可，无需 Node。WSL 产物在 `out/wsl/motion/`。

## 烧录文件

按用户要求，本次没有烧录，也没有执行任何电机动作。最终交付目录包括以下分离镜像；不要把 `firmware.bin` 烧到 0 地址。

| 文件 | Flash 地址 |
| --- | --- |
| bootloader.bin | 0x0000 |
| partitions.bin | 0x8000 |
| boot_app0.bin | 0xE000 |
| firmware.bin | 0x10000 |

`firmware.elf` 用于调试与符号解析，不直接烧录。推荐以后在确认端口后，用原工程 `pio run -d device-controller -t upload --upload-port 实际端口` 上传；不要擦除整片 Flash 来更新网页，否则会清掉已保存的 Wi-Fi NVS。

## 验证与剩余事项

已通过：UART 协议测试、133 项 MotionCore 检查、679 项控制器检查、21 项网页组帧／规划测试；12 组 Playwright 交互验收直接加载最终嵌入 HTML，并模拟板端 HTTP 接口。桌面视口为 1513×1039、1280×800。旧网页测试入口已改为统一调用新版工作台测试。

浏览器测试覆盖无上电自动 POST、真实 F3/CD 请求、断线清空、非法地址、HEX 地址不匹配、在途请求期间全局停止，以及 Wi-Fi 扫描／连接／忘记。固件测试覆盖协议截断与越界拒绝、5 秒板端停止、反馈过期、发送失败、使能 ACK、到位确认及 bus-off。

这些是编译、主机和模拟 HTTP 测试，不是实板验收。实际 CAN 电机型号／固件响应、接线、AP/STA 切换与物理停止仍须上板验证。未支持的指令已明确禁用；本版不声称驱动所有功能都能直接执行。
