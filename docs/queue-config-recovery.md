# 编排使能与回零配置修复

## 行为

- 显式 `enable 1` 总会重新发送 F3，不再因板端缓存为已使能而跳过；F3 ACK 和本次请求之后的 3A 使能标志都满足才确认使能。
- 同一电机的可恢复故障允许队列通过新鲜静止反馈和显式 enable 恢复，不能绕过全局故障。
- 完整的 4C 回零配置逻辑帧保持原字节发送，等待 ACK，再读取 22 比较 15 字节参数。队列等待核验结果后才执行下一步；拒绝、超时、不一致分别报错，不自动重发配置。
- `/api/config-result` 保存最近一次配置结果。网页独立显示提交值、读回值与差异，持续状态轮询不会清掉结果；断线时保留结果并标记过期。
- CD 相对移动采用用户保存的单步时长上限，失败记录保留目标、实际位置、速度和耗时。原始帧程序结束显示“发送结束”，不表示机械动作完成。

## 验证与限制

原生测试覆盖冷启动 enable + move、ACK 与使能反馈的先后顺序、4C 配置屏障、错误地址和乱序回包、拒绝／超时／不一致，以及故障后队列恢复。浏览器测试覆盖结果保留、断线、差异展示和桌面布局。

示例 `move 1 -20 mm 300 300 300 200` 在 ID 1 的 rotation distance 为 2 mm/rev 时编码为 -3600°，需要前置 `enable 1`。

本次验证使用模拟 CAN 与浏览器接口，未烧录、未驱动实机；软件缺陷已覆盖，但不能据此断定硬件故障的唯一原因。协议没有事务序号，极迟到的同地址同功能码 ACK 仍有相关性限制。独立 CAN 原始分包不重建成配置事务；仅完整 hex 4C 逻辑帧及指令实验室的 4C 配置接入读回核验。
