# 使能与回零配置读回

描述对象：当前 Motion 控制器的使能确认和指令实验室 4C 配置结果，以及普通队列的区别。Milestone：V1，`V1-device`，UART v4。历史修复的主机验证不代表真实驱动验收，普通编排以 [队列说明](motor-queue.md) 为准。

## 行为

- 普通队列的 `enable ID` 显式发送 F3 后继续，不自动等待使能确认；网页受监督使能需匹配 F3 ACK 与本次请求后的 3A 标志才确认。不要把队列发送结束当作驱动已使能。
- 普通队列不套用控制器故障或试动策略；显式 await、同步和产品流程仍按各自证据判定。受监督控制器的故障恢复不能用来宣称未知轴已安全。
- 指令实验室的完整 4C 配置保持原字节发送，等待 ACK，再读 22 比较 15 字节参数；拒绝、超时、不一致分别报告，不自动重发。普通队列 `hex/can` 是直发，不自动创建或等待此配置事务。
- `/api/config-result` 保存最近一次配置结果。网页独立显示提交值、读回值与差异，持续状态轮询不会清掉结果；断线时保留结果并标记过期。
- 常规 CD 受监督移动采用保存的时长策略并记录失败证据；普通队列只在显式 `await` 时等反馈，不偷偷加同一时长门禁。原始帧程序结束显示“发送结束”，不表示机械动作完成。

## 验证与限制

原生测试覆盖冷启动 enable + move、ACK 与使能反馈的先后顺序、4C 配置屏障、错误地址和乱序回包、拒绝／超时／不一致，以及故障后队列恢复。浏览器测试覆盖结果保留、断线、差异展示和桌面布局。

示例 `move 1 -20 mm 300 300 300 200` 在 ID 1 的 rotation distance 为 2 mm/rev 时编码为 -3600°。如需使能，操作者先显式写 `enable 1`；普通直发不自动补使能或等待其确认。本例不是机构安全参数，不能直接套到实际行程。

首次修复验证使用模拟 CAN 与浏览器接口，不据此断定硬件故障的唯一原因。协议没有事务序号，极迟到的同地址同功能码 ACK 仍有相关性限制。指令实验室/控制器的完整 4C 逻辑帧可接读回核验；普通队列 raw 和独立 CAN 分包不自动重建配置事务。参数读回一致仍需实机核对单位、碰撞阈值和机械风险。
