# 电机执行修复与低带宽同步计划

更新：2026-09-23。本文记录已确认的实施方向，**不是现有功能说明**。本次仅更新文档；新语法、状态字段、调度器及同步监测尚未实现。

## 当前证据与边界

- 用户实机反馈：两条不同电机的 `move`，仅一台运动；完整指令及抓包尚未取得，根因未确认。
- 代码中普通 `move` 发送后继续，没有等前一台到位的门禁，但非等待动作未逐条确认驱动接受。
- 底层支持 `sync=1` 缓存及 `00 FF 66 6B` 广播触发，普通队列尚未组织同步组。
- 常规查询约每 30 ms 调度，`await` 另有 50 ms 查询循环，部分查询还会额外叠加；尚无统一预算。这不是驱动吞吐量测量。
- 本次讨论期间 `python tools/test_motion.py` 通过；使用模拟总线，不能证明实机双电机执行、同步精度或驱动处理上限。未烧录或进行实机验收。

## 1. 双 move 与异常信息

- 排查解析、不同地址、真实 CAN 分包、发送顺序和失败处理。实机对照分别执行、连续执行、交换顺序、加入短间隔，依据应答和位置定位原因；不预先用延时或重发掩盖问题。
- 普通队列保留直接发送语义；后台被动观察已有应答，不加隐式等待、确认查询、自动重试或自动停止。未收到接受应答显示“接收未确认”，不能报告执行成功。
- 事件关联运行、循环、源行、电机、功能码和时间。同轴同功能码迟到应答无法归属时标记不确定；发送结束后仍保留诊断。
- 保留队列 API 原字段，扩展确认程度、成员状态、同步阶段及有界事件记录，缓冲溢出明确报告。
- 执行区顶部突出异常，支持定位指令、查看详情；轮询不能冲掉异常。区分发送结束、驱动接受、机械完成及停止未确认。
- 长协议说明与语法解释默认收起，主界面优先状态和操作。日志利用已有 TX/RX，不额外查询驱动。修改网页源码后通过 `build:device` 生成设备页面。

## 2. CAN 带宽约束

- 控制器、await、同步组共用一个查询调度器，按电机与字段合并需求；限制总速率、间距、在途数量及突发量，不在延迟后补发欠账。
- 同字段在途请求不重复发送；超时不立即重试。页面读板端缓存，多窗口和 HTTP 刷新率不能使 CAN 查询成倍增长。
- 空闲只低频更新所需字段；准备阶段获取位置、使能和静止证据；运行优先成员位置，故障状态低频查询，电流默认不周期查询；接近结束时在预算内增加位置/速度确认，完成后释放需求。
- 目标在确认且未被新命令改变后不反复读取。新鲜反馈证据仍需晚于对应动作，不能用去重为由接受旧缓存。
- 停止优先，正常动作优先于可选遥测；同步缓存阶段暂停无关查询，保持分包连续及协议间隔。原始报文不改写、不重排，其流量计入预算统计。
- 预算通过独立台架测试确定并显式保存，不从 CAN 波特率推断驱动处理能力；运动中不自动探测吞吐极限。
- 若预算无法满足当前同步速度和容差所需的监测能力，启动前拒绝；运行中持续无法判断则请求整组停止，不无限提高轮询频率。
- 统计 TX/RX、查询量、应答延迟、未应答、发送错误及可观测 RX 丢失。总线占用估算不等于驱动负载，无法观察的丢包不能记作零。
- 首版不依赖未经验证的批量命令或主动周期反馈，不在线发送轨迹点。

## 3. 同步组和拧瓶盖

计划新增 `sync begin` / `sync end`，组内支持 2–8 个不同电机的相对 `move`；禁止嵌套、重复 ID、广播成员及原始帧。整组隐式等待全部完成再继续。**当前解析器不支持这些语法。**

- 所有轴共享进度曲线 `s(t)`，各轴位置为起点加总位移乘以 `s(t)`。由最严格的各轴速度、加减速度约束生成共同梯形或三角形曲线。
- 一次下发完整驱动参数；量化后重新检查比例及时间误差，不能满足容差则拒绝，不静默裁剪。
- 新增 `helix` 动作与表单生成器，板端负责换算：线性位移 = 螺纹导程 × 瓶盖旋转圈数。导程指每圈轴向移动量，不混同多头螺纹的牙距。
- 必填机械配置：轴 ID、方向、线性 mm/rev、旋转传动比、导程、运动限制及配合容差；不猜默认值。螺纹脱离不自动识别，抬升单独编排。
- 首版只做比例规划与误差监测，不在线追赶补偿。低频反馈不能保证采样间隔内的实际连续精度。

## 4. 执行与故障边界

状态机：检查 → 缓存 → 准备确认 → 单次广播触发 → 监测 → 全部到位；另有异常停止和停止未确认状态。

- 启动前成员必须已使能、静止且反馈新鲜，不自动补使能。全部缓存接受后才广播触发。
- 同步动作独占运动入口，查询及停止可用。成员拒绝、发送失败、超时、超差或持续监测不足时，终止后续步骤并请求成员整组停止，保留使能，不自动重试或恢复。
- 每个成员独立确认目标及新鲜静止反馈，全部通过才完成。反馈判断考虑采样时间差、应答延迟及运动界限，不能直接相减不同时间的位置来判定比例异常。
- 螺旋动作监测实际轴向位移与导程乘实际转数的差，报告可观测偏差及不确定性。
- 必须实测缓存覆盖/清除、停止与广播的行为。部分准备失败后不能再次自动触发；原始同步报文或重启导致缓存未知时，不得假定广播只作用于当前成员。缓存清理及非成员隔离未验证前，不通过同步实机验收。

## 5. 验收与文档维护

1. 普通队列测试：不同地址双 move、真实分包、拒绝、无应答、迟到应答、同轴覆盖、循环、await 与原始帧回归。
2. 调度测试：合并查询、在途限制、合计预算、无突发补发、离线目标不阻塞其它轴、停止优先、多浏览器不增加查询。
3. 同步测试：异向、不同传动比、短行程、量化、部分缓存失败、触发失败、超差、反馈不足和停止未确认。
4. 网页异常可见性与两个桌面视口验收；网页/固件测试、设备页面构建及 Motion 编译，检查内存与栈。
5. 实机先定位双 move，再独立测查询负载和应答质量，最后空载同步与低速拧盖。吞吐测试不与拧盖同时进行；记录单位动作帧数、启动/到达偏差及可观测配合误差。
