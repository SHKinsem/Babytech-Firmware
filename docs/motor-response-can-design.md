# X42S 回执模式与 CAN 预算：控制架构约束

依据本仓库保存的 [X42S 第二代手册 V1.0.5](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md)，并对照当前 `MotorControl`、`CommandQueue`、`SyncRuntime` 和 `CanQueryScheduler`。这是设计约束与兼容性盘点；本次迁移在手动操作结果中分别记录已收到的 `02` 和 `9F`，不写入电机 Response 配置，也不改变查询速率或运动完成判据。

## 回执不是同一种完成

手册的 [Response 菜单（p18–19）](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-18)只作用于控制动作，参数读取/修改不受它控制。默认是 `Receive`。控制回复 `02` 表示收到，`9F` 是手册明确列出的**位置到达、回零完成或力矩夹爪夹紧**主动回复；不能推断使能、停止或连续速度动作都有完成事件。`E2`/`EE` 是拒绝或格式错误，回零的 `12`/`22` 可表示已在零点或限位而没有运动。状态读取 `3B` 的“未在回零且未失败”也可能是上电默认值，不能单独证明本次回零成功。[控制回复 p40、CAN p43](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-40)、[回零状态 p63](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-63)。

| 电机 Response | 手册承诺的动作回复 | 与当前运行路径的关系 |
| --- | --- | --- |
| `None` | 不回 `02`、不主动回 `9F` | 当前 move/home/Sync 依赖接收证据，不能作为兼容配置。 |
| `Receive`（默认） | 收到后回 `02`，不主动回 `9F` | 当前代码依赖的默认配置；现场每台设备仍需读回确认。完成由指令后的新鲜目标、位置、速度及回零状态证明。 |
| `Reached` | 对有完成回复定义的动作，结束后才回 `9F` | 长动作可能超过当前 move/home 的 1500 ms ACK 窗口；Sync 缓存阶段等待 `02` 才发送广播触发，因此不能直接切换。 |
| `Both` | `02`，以及有定义时的完成回复 `9F` | 当前路径可接收两类回复，但不得把迟到的 `9F` 当作下一次同功能码指令的完成证据。上线前仍需按设备固件实测。 |
| `Other` | 位置动作回 `9F`，其他控制动作回 `02` | 位置长动作有同样的 ACK 超时风险；不能假定它等价于 `Receive`。 |

新控制契约应分开记录四件事：`Sent`（CAN 已提交）、`Accepted`（当前操作收到可信的接收回执）、`DriverReached`（收到对应操作的 `9F`）、`PhysicallySettled`（指令后的目标与位置、速度、回零状态等新鲜证据满足相应操作规则）。当前手动操作结果只实现活动期间的 `02`/`9F` 证据分离，尚未按设备 Response 模式改变策略或对外发布上述完整阶段。手册帧没有主机事务编号，单个迟到 `02`/`9F` 不能无条件归属新操作；操作终结后才来的 `9F` 不追加到历史。`DriverReached` 可用于未来的优先补查，但目前不额外发查询，也不独自完成手动运动、回零或 Sync；驱动自身的到位窗口默认为约 0.8°，不能代替项目按不同操作设置的目标容差与新鲜静止证据。[到位定义 p36、p87](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-36)。超时后也不能推断机械已经停下。未带 `await` 的旧 DSL 仍按发送完成推进，旧队列 `Done` 不表示轴已静止。

当前固件在 [MotorControl](../device-controller/src/MotorControl.cpp)中对普通手动 move 使用本机计算目标、ACK 和两组新鲜位置/速度；FB/CB 直通位置还要求驱动 `33` 新目标。home 使用本次运行的 `3B` 变化或 `9F`，再按证据路径核对新鲜静止反馈；[SyncRuntime](../device-controller/include/SyncRuntime.h)保留缓存 `02`、单次 `FF` 触发与触发后取证。迁移期保留这些规则。将来支持非默认 Response 时，先读回设备固件类型及完整配置，再显式选择超时/证据策略；X 与 Emm 的配置结构不同，不能只写一个 Response 字节。[配置读取和修改 p99–103](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-99)。

## 一块板共享一个 CAN 预算

当前总线是 500 kbit/s 的扩展帧。自动查询由 [CanQueryScheduler](../device-controller/include/CanQueryScheduler.h)统一派发：默认全板最多 10 次查询/秒、至少 100 ms 间隔、最多 2 次在途；Sync 使用**同一个预算**并暂时排除其他自动查询。页面、Demo、手动监督和 Sync 的需求会在同一调度器竞争。Demo 约每 20 ms 登记一个字段需求，登记速度并不等于实际发送速度。原始调试帧和直接控制帧不受自动查询配额限制，因此评估带宽时必须另计。

手册的 [CAN 分包规则（p42–43）](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-42)要求每包重复功能码、每包最多 7 个后续数据字节；较长控制命令可能占多个 TX 帧，回复和重试也占总线。以无位填充、无重试的经典 CAN 扩展帧粗估，一帧含帧间隔约 `67 + 8 × DLC` bit：一次 `3A` 或 `3B` 读取及回复约 174 bit，两个分别读取约 348 bit；[手册 p74 的 `3C` 联合状态读取](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-74)约 182 bit，理论上可节省这两类状态查询近一半的线时。现有解析器/调度器尚未支持 `3C`，必须先验证字段、帧格式和新鲜度，再考虑替换，不能为了节省帧数改变 Sync 证据。

在默认 10 次/秒预算下，单次请求加单次回复的基础流量通常远低于 500 kbit/s，但**采样时延**已经是约束：Sync 准入按每轴 5 个字段的保守覆盖预算估算，5 轴约 2.5 秒、8 轴约 4 秒，另加回复余量；这不是每次运行实测的最低采样时间，已有新鲜缓存和实际响应速度会影响耗时。仍不能据此承诺多轴高速同步的完成延迟。历史 30 次/秒、两轴的实机记录不能外推到 5–8 轴。[SyncRuntime](../device-controller/include/SyncRuntime.h)按当前预算计算准入和时间窗口。

手册还提供 [周期回传（p66–67）](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-66)。它绕开主机逐次查询，但不能直接开启高频：例如 5 轴各以 1 ms 周期回报一个 7 字节字段，单是扩展帧基础线时就约 615 kbit/s，已经超过当前波特率，尚未计位填充和重试。手册对 X42S/Y42 定时返回的适用表述不完全一致，启用前还需对实际 X 固件核对。当前接收循环每轮最多处理 16 帧，TWAI RX 队列为 20；突发也可能先造成丢帧，再造成错误的“反馈过期”。

手册的 `AA` 多电机指令另有接收回执归属和内嵌同步位语义；它不能直接替换现有的逐轴缓存、逐轴确认、单次 `FF` 广播的 Sync 路径。[多电机命令 p49–50](ZDT_X42S/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.md#page-49)。

后续改预算或使用主动回传前，须在实际电机数量与网页/Demo/Sync 并发下记录：总 TX/RX 帧率、分包和 `9F` 数量、查询排队/超时、最老有效反馈年龄、TWAI RX overrun、停止帧发送延迟，以及异常/重试。对控制与停止保留优先级，给自动查询明确总量上限；任何 `3C` 合并或回传策略都要以 CAN trace 和机械结果复验。
