# 设备板控制逻辑：重构前行为基线

记录日期：2026-09-25。代码基线：`main` 的 `2308aad`。本文件记录当前实现及软件回归，供[分阶段执行路线](device-control-refactor-execution.md)比较；不代表新架构已经落地，也不构成新固件的实机验收。

## 必须保留的现有语义

| 入口或能力 | 当前行为 | 迁移时的检查点 |
| --- | --- | --- |
| 队列 DSL | `CommandQueue` 在发送前解析并校验整份程序；最多 64 步、8192 字节，重复次数有上限。无效程序不发送 CAN 帧。 | 保留原语法、单位、拒绝行为及原子校验；新增语法另行版本化。 |
| 普通队列指令 | 未写 `await` 的动作通常在发送成功后推进；程序行耗尽不证明电机静止。 | 不把发送成功或 HTTP 202 报成机械完成。 |
| `move/home await` | 等待相应 ACK、新鲜目标或回零证据，以及不同时间取得的静止位置/速度反馈。 | 旧反馈、单次样本、迟到 ACK 不得完成新指令。 |
| 手动控制 | `MotorControl` 的手动运动要求确认使能、新鲜静止反馈和策略限值；队列发送遵循自身旧契约。 | 迁移到公共入口时不能直接用队列语义覆盖手动安全门。 |
| Sync | `SyncRuntime` 先预检、缓存各轴 CD 并确认，再发单次 FF；触发后读取新目标，按新鲜反馈判断完成。失败停止仍跟踪证据。 | 保留帧顺序、目标窗口、独占查询预算及停止覆盖；不把 Sync 拆成逐轴普通移动。 |
| 查询 | `CanQueryScheduler` 合并 Controller、Await、Sync、Page、Demo 的需求；生产主循环在显式停止及队列推进后统一派发查询。 | 页面和 Demo 不能饿死 `await` 所需的目标/位置/速度反馈；状态读取不应额外发私有查询。 |
| 停止与取消 | 主循环在 Demo/队列继续推进前处理显式停止；已发送运动与软件队列状态是两件事。 | 取消后无新动作；停止未确认时不能声称硬件静止。 |

这些是当前实现的行为边界，部分行为仍待在后续阶段明确更严格的执行权与超时策略。P2 的总线封装仅改变代码所有权，不改变上述语义。

## 软件证据

在 `2308aad` 上、任何运行时代码改动前，本机运行下列命令，均返回 0：

- `python tools/test_protocol.py`：UART 帧、重复请求、停止与重连。
- `python tools/test_motion.py`：查询预算、Sync 规划/运行、手动电机监督、队列与 UART 组合。
- `python tools/test_raw_can.py`：真实协议组帧、队列与 Sync CAN 帧顺序。
- `python tools/test_demo.py`：Demo、五轴后台查询与 `move await → home` 组合。

原版 `tests/test_demo_motor.cpp` 的五轴回归没有把 Page 读取和上述 Demo/队列场景放在同一测试里；本分支已补此组合及 Sync 独占窗口的实际查询断言。软件回归使用模拟 CAN，不能证明真实电机的时序、负载、失联停止或新镜像的 Sync 结果。本机 PlatformIO 6.1.19 位于用户目录但未加入 `PATH`。
