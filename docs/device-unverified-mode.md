# 设备板不校验模式

设备板网页顶部的「不校验模式」开关写入设备板 NVS；重启后保持上次选择。默认关闭。也可通过 `GET /api/control/mode` 查询，或向同一路径 `POST unverified=1` 开启、`POST unverified=0` 关闭。只有保存成功才切换运行状态。`GET /api/status` 的顶层 `unverifiedMode` 显示当前状态。

开启后，设备板的 HTTP 电机指令、直接接入的 Brain v2 UART 指令和内置 DISPLAY Demo 共用直通派发：发送方给出能够编码为协议字节的指令，设备板不再要求使能确认、位置/速度反馈、到位判断、ACK、故障清除或调试限值才发送。原始十六进制指令保持原字节；手动 CD 指令按协议的 0.1 单位精确编码。无反馈时也不自动补发查询、重试或停止帧。CAN TX 失败仍会返回失败；语法错误、长度错误和无法无损编码的字段仍被拒绝，避免发出与输入不同的字节。

队列和 Demo 保持原有指令顺序、显式 `wait` 时间、原始帧间隔与 Sync 组的单次触发；`await`、同步完成和 Demo 到位条件在此模式不等待电机反馈。队列或 UART 返回的完成仅表示指令已发送或脚本已发完，**不表示电机到位**。显式停止或失能会在本地取消尚未发送的队列和 Demo 步骤，并只发送该请求对应的停止或失能帧。同步组从缓存指令到触发帧期间，其他非停止指令会短暂返回 `sync_batch_active`，防止插入并改变线序。切换模式本身不发送电机帧；「清除板端状态」只清理本地软件占用，在此模式不隐式发送停止帧。

不校验模式开启期间，设备板不允许开始 OTA；本次开机曾直通发送可能引起运动的指令后，即使关闭开关，OTA 仍保持关闭。这个记录在重启后清空，**重启本身不证明电机已停止**。开启时正在等待反馈的队列或 Demo 会转为直通继续发送；若队列或 Demo 仍在执行，关闭开关返回 `control_mode_busy`，先显式停止再关闭。关闭后，后续新操作恢复原有监督与门禁；需要按正常流程重新使能。

此开关位于**设备板**。直接送到设备板的 UART v2 请求受它控制；`main-controller` 的旧网页仍有自己的参数范围、版本和忙碌门禁，也没有查询或修改这个开关的 UART 协议。若从主控板旧网页操作，页面可能在发出 UART 请求前就拒绝；设备板网页可直接使用本开关和直通入口。

主机测试与固件编译可检查编码、帧序和无反馈路径；CAN 带宽、实机动作和停止结果仍需在台架记录 CAN trace 与机械观察。默认 Receive 回执设置不需要改动。
