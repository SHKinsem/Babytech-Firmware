# 新控制接口的行为契约草案

状态：目标契约，尚未整体实现。本文规定后续重构要能观察和验证的行为，不指定最终 HTTP 路由、UART 帧格式或 DSL 文法。本分支的 `DeviceAPI` 已提供类型化派发、只读快照，以及**仅在当前固件进程内**使用的手动操作编号与有界结果查询：一个活动 Move/DirectPosition/Home 和最多八条终态记录。程序 `runId` 与手动 `operationId` 分开；旧 HTTP/UART/Demo 报文尚未暴露后者。结果分别记录本次活动操作匹配的 `02` 接收回复与 `9F` 驱动完成回复；两者都不等同于新鲜反馈证明的物理到位，停止后仍需另看 `stopPending`。终态之后到达的 `9F` 不追加到历史；协议无事务编号，同地址同功能码的迟到回复也无法绝对归属。程序顺序状态已迁入 `ProgramRunner`，旧 DSL、CAN 与 `SyncRuntime` 行为保持。不能据此宣称下表所有长期契约已经验收。旧 `MotorControl`、`CommandQueue` 测试属于迁移基线，新的 DeviceAPI/监督器测试属于当前接口契约。电机回执模式和总线预算见[专项评估](motor-response-can-design.md)。

## 请求、结果与观测

| 场景 | 新接口需要表达的事实 | 验收测试观察 |
| --- | --- | --- |
| 提交动作或程序 | 请求是否被接收，以及拒绝原因；接收不代表已发 CAN、更不代表机械完成。 | 接收、忙碌、参数无效、容量不足分开报告；无效请求不产生运动帧。 |
| 跟踪一次执行 | 可关联提交与后续阶段、最终结果；发送、协议确认、真实到位证据不混用。 | 迟到 ACK 和旧反馈不能完成新操作；结果历史达到上限时行为明确。 |
| 读取设备状态 | 带采样时间、有效性和来源的硬件观测，与期望目标及程序进度分开。 | 重复读取状态不额外发送私有 CAN 查询；过期或无效样本不放行等待条件。 |
| 停止和取消 | 先阻止未发动作，再请求实际停止；停止结果与停止证据分别记录。 | 普通请求队列满时仍能停止；取消后不再发送后续运动；反馈不充分时不报告已静止。 |
| Sync 组 | 多轴作为一次受约束的操作，保留缓存、确认、单次触发和新鲜反馈证据。 | CAN trace 与有效结果均满足同步约束；不能通过逐轴普通运动冒充。 |
| 程序存储和运行 | 保存、校验、版本及一次运行的执行状态彼此分离。 | 无效保存不覆盖旧版；保存不启动；运行中编辑不改变本次版本。 |

## 测试结构

当前手动编号在同一个监督器实例中单调递增；`begin()` 开始新会话并清除 RAM 历史，旧编号返回 `Expired`。终态环覆盖最老记录时返回 `Evicted`，未发出的编号返回 `Unknown`。读取结果不发送 CAN，也不登记查询。编号未进入对外协议，**不承诺设备断电重启后的全局唯一性**；未来若要通过 HTTP/UART 查询，必须先设计启动会话标识和版本化字段。

取消、禁用或程序接管只说明本地操作监督已终结；不能把 `Cancelled` 当作驱动实际禁用或已停稳。广播禁用发送失败会保留故障与已知节点的停止等待；发送成功后，已知节点也须在新的禁用标志之后取得静止反馈才解除等待。控制重置保留这些硬件证据。旧队列的非 `await`/原始动作结束后仍可能有未证明的运动；跨入口执行权及其 OTA 门禁留待后续阶段处理并经实机复验。

1. **迁移基线**：当前主机测试使用现有类和模拟 CAN，判断无行为变化的搬迁是否意外改变线序、预算或完成证据。旧适配器退出后，相关测试可更新或退休。
2. **新接口契约测试**：通过即将定稿的请求/结果/快照边界驱动真实服务组合；模拟层只提供时钟、CAN、存储和传感器输入，不直接制造业务结果。测试只依赖公开行为，不直接断言内部类名、tick 次数或对象布局。
3. **实机验收**：记录提交、构建配置、镜像哈希、CAN trace 与机械结果，覆盖 Sync、停止、离线、负载及 OTA 互斥。软件测试或编译通过均不替代这一层。

## 接口定稿前的开放问题

- 哪些旧 HTTP/UART/DSL 入口需要迁移期兼容，哪些可版本化替换；旧适配器退出条件是什么？
- `Sent` 后仍在运动的操作何时释放执行权；OTA/新程序何时可以接管？
- 每类操作支持的确认层级、超时和失败后的实际停止策略是什么？
- 请求、活动指令、结果历史和程序容量各自的上限是多少？
- 外部是否需要订阅进度，或仅通过带操作编号的状态查询获取？

这些决策先影响新契约与验收测试，再影响实现；不要反过来把现有 C++ 方法直接当成目标接口。
