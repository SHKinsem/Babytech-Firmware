# 本次工作台开发复盘

依据：`tools/motor-protocol-demo/claude-brief.txt`、`claude-review.txt`、`claude-development.md`、`design-qa.md`、浏览器测试结果，以及保留的一次失败 CLI 运行记录。没有完整可靠的阶段工时数据，下列排序是按返工量与执行过程判断，不虚构占比。

## 时间主要花在哪里

1. **协议与异步状态的返工。** 首轮之后一次集中提出 10 类修复：运行时缺失导入、错误测试期望、方向字段无效、HEX 校验绕过、全局停止广播不正确、切换电机后旧任务继续、同步提前改状态、对未知模式模拟成功、变体选择比较错误、布局与图标不符合约定。第二轮后仍发现复制帧缺失导入和同步状态更新问题。主要成本是发现、复现、交回修复及复测。
2. **从纯模拟界面接到真实固件。** 这是用户后续追加的合理范围，不能全部计为首轮浪费。实际工作包括独立实机入口、真实 API 和反馈、板端命令校验、速度／力矩监督、真实收发记录、Wi-Fi 互斥、HTML 内嵌、WSL 编译及交付包。首轮若把 UI、协议和传输接口分开，可以降低后续成本，无需提前实现未请求的硬件功能。
3. **运行环境排障。** Claude Code 使用 DeepSeek，并不代表走 Anthropic。保留的一次 retry-only 运行从 10:42:21 UTC 到 10:46:11 UTC，约 3 分 50 秒，没有实现进展。之后通过已存在的本机代理恢复访问；npm 网络／缓存权限、Windows PowerShell 与 Bash 环境不一致是另外的问题。它们不是模型代码能力问题。
4. **范围外的小返工。** Codex 后期做了手机适配与验收，用户随后明确暂不需要；属于统筹范围控制不当。打包时宽泛递归 docs 还带入了无关 STM32 示例，随后改为白名单。它们不应归因于 Claude Code 或 DeepSeek。

## 能提前避免什么

| 大任务一次写完，缺失导入到浏览器才发现 | 分成协议模块、最小 UI、异步操作三个检查点；每一步运行独立检查后再继续 |
| 代码与测试都由同一执行者编写，错误期望相互印证 | Codex 从 C++ 源码提前给出少量独立报文／数值基准；Claude 实现后进行交叉验证 |
| 原始 HEX 绕过表单校验，地址不一致 | 把“表单与 HEX 使用同一验证路径、地址一致”列为接口契约和负面验收，不只写在长说明里 |
| 同步、停止、切换地址、延迟回调相互影响 | 单独分配状态转换模块，给出操作—状态—允许事件表；测试先同步再停止／失能／切换等序列 |
| 原型接实机时重写状态逻辑 | UI 不直接生成模拟 RX；采用显式模拟传输边界。仅在获准接实机后实现设备传输 |
| 图标、复制、字符串变体选择遗漏 | 提交前执行点击真实控件的浏览器冒烟，不以打包成功代替页面运行 |
| 自行增加手机工作 | brief 明确目标设备和视口；后续变更只更新受影响的验收范围 |

## 更合适的分工

- **Codex：** 确认当前范围与运行环境，提取协议／API 契约和独立基准，指定文件归属，负责浏览器及编译验收、实机集成审查和交付。不会和执行者同时修改同一文件。
- **Claude Code + 配置的 DeepSeek：** 按已确认契约实现分配的模块，提交变更文件、已运行与未运行的检查、未知语义和阻塞；收到失败复现后修复自身负责的代码。
- **推进顺序：** 协议编码／校验 → 可渲染最小页面 → 交互与状态 → 已授权的真实 API 集成 → 桌面验收与打包。小任务可以合并步骤，无需机械增加轮次。

这能提前发现或减少返工，但不能保证模型不再出错。原始 brief 已覆盖很多后来失败的要求，关键改进是把要求变成短检查点和外部验证，而不是继续堆长提示词。

技能更新目标为现有 `deepseek-driven-dev`：强化任务契约、工具与责任匹配、独立协议基准、阶段验收、模拟边界和不扩范围。未修改模型、全局代理或认证配置。
