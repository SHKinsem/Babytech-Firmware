# 电机编排队列

对象：当前 Motion 板直发队列、显式 await、执行诊断、共享查询调度和独立同步组。阶段：低带宽同步首版软件实现；尚未完成实机验收。本文说明当前接口与操作边界，不把主机测试当成机械动作证明；验收证据见 [开发记录](motion-sync-development.md)。

网页「编排队列」将整段程序交给 Motion 板执行。先检查全部行，再开始发送；错误不会自动重试。浏览器断开不取消已开始的程序，板卡重启不恢复程序。程序草稿留在浏览器，电机换算参数保存到板端 NVS。

## 最短实用示例

```text
enable 1
move 1 20 mm await
enable 2
home 2 await
enable 3
torque 3 800 1500
```

依次使能电机 1 并移动 20 mm、使能电机 2 并回零、使能电机 3 并以 800 mA 限速力矩运行 1500 ms，然后停止。力矩单位为电流 mA，不是 Nm。默认发送后继续；只有 move/home 末尾带 `await` 才等待本次动作完成。停止保留使能；需要释放保持力时加 `disable ID`。

在「旋转距离」中按 ID 设置 **rotation distance = 电机转一圈的实际行程（mm/rev）**。例如电机 1 为 8 mm/rev，20 mm 对应 900°；电机 2 为 40 mm/rev，20 mm 对应 180°。没有配置不能执行该电机的毫米动作，但仍可用 `deg` 或 `rev`。换算以板端已保存的值为准，不以未保存表单为准。

## 指令

| 写法 | 含义 |
| --- | --- |
| `enable ID` / `disable ID` | 只发送使能／失能帧，不等待应答或静止 |
| `move ID 数值 [deg或rev或mm] [转速 [加速 [减速 [电流]]]] [await]` | 相对当前实际位置运动；默认 °、30 RPM、60 RPM/s、60 RPM/s、800 mA |
| `home ID [模式] [await]` | 回零；默认 0 单圈就近，1 单圈方向，2 碰撞，3 限位，4 绝对零点，5 上次掉电位置 |
| `torque ID 有符号电流 持续毫秒 [限速RPM [电流斜率]]` | C5 限速力矩；默认 30 RPM、1000 mA/s；计时到后发送停止帧并继续 |
| `velocity ID 有符号RPM 持续毫秒 [加速 [电流]]` | C6 限流速度；默认 60 RPM/s、800 mA；计时到后发送停止帧并继续 |
| `stop ID` | 发送停止帧后继续，保留使能 |
| `wait 毫秒` | 板端等待；不会阻塞网页、反馈采集或停止按钮 |
| `hex AA BB ...` | 逻辑 X 协议报文，包括地址、功能码、末尾校验；自动按既有 CAN 规则分包 |
| `can ext或std 十六进制ID 数据字节...` | 原样发送一帧 CAN 数据帧，不添加校验、不改写 ID |
| `sync begin` / `sync end` | 包围 2–8 个不同电机的相对 move；隐式等待全部到位；禁止嵌套、广播、重复 ID、组内原始帧及 await |
| `helix 旋转ID 直线ID 圈数 导程 传动比 旋转方向 直线方向 RPM 加速 减速 电流 轴向容差mm` | 板端展开为双轴同步组；所有参数必填，直线轴使用已保存的 mm/rev |

负数表示反向。`#` 后是注释。循环次数控制整段程序重复。当前固定容量 64 个动作、8192 字节文本、1–1000 轮；这些是执行器容量，不是驱动协议的能力限制。编排只检查协议字段范围、单位换算和容量，不套用手动试验限制。torque/velocity 省略持续时间时只发送，不自动停止。

## 直通示例

```text
# 原样发送一帧标准 CAN
can std 123 DE AD
# 广播触发已缓存的 X 协议同步指令
hex 00 FF 66 6B
```

直通不受功能码白名单或运动参数策略限制，只检查帧格式和容量。它可以发送同步及特殊功能，但页面无法替未知报文判断动作完成。原始帧队列结束只表示提交发送结束，不表示电机停止。需要节奏时加 `wait`；需要结束动作时明确发送对应的停止指令。取消队列／全部停止会中止后续步骤并请求回零中断和停止。

回零 `02` 应答仅表示已接收；默认 `3B 00` 也不证明回零完成。板端结合本次回零状态变化、明确完成应答及新鲜静止反馈判定。已在零点或限位触发导致未运动会单独报告。

## API

执行状态新增 `diagnostics`（最多 64 条）、`diagnosticsDropped` 和独立保留的首个 `alert`。每条含运行、轮次、源行、电机、功能码、发送/应答时间和返回码。`submitted` 只是提交发送；`driver_accepted` 来自 02；`driver_completion_reported` 不等同机械到位。2 秒未见应答标记 `receive_unconfirmed`，不延迟队列、不查询、不重试、不停止。同轴同功能码再次发送时，迟到应答无法排除，标记 `association_uncertain`；这一不确定性跨运行保留。记录淘汰不会清掉首个异常，新运行才清掉首个异常标记。

`GET /api/query-budget` 读取唯一查询调度器的配置及统计，不发送 CAN。`POST /api/query-budget` 显式保存 `queriesPerSecond`、`gapMs`、`timeoutMs`、`cooldownMs`、`maxInflight` 到 NVS；运行或在途时拒绝修改。首次配置为 10 次/s、100ms 间隔、500ms 应答超时、500ms 超时冷却、2 个在途，突发固定最多 1 次。该值未经台架吞吐验证，`benchValidated=false`，不能当作驱动能力承诺。

控制器、await、同步组、4C 后的配置读回共用预算。相同 ID+字段合并，在途不重复；超时释放槽但经过冷却才允许后续需求再次发送。页面状态访问只续订低频缓存需求，增加浏览器不增加预算。默认不周期查询电流。原始帧与运动照原字节发送，它们的 TX 会推迟可选查询。未知设备流量及不可观测的驱动丢包显示未知，不报为零。

工作台执行区顶部保留首个异常，可定位源行和展开详情；普通 `done` 显示“发送结束”，取消显示停止待确认。说明文字默认折叠。设备页仍由 `npm run build:device` 从源码生成。

`GET /api/queue` 查询执行进度；`POST /api/queue/start` 接收表单 `program`、`repeat`；`POST /api/queue/cancel` 取消。`GET /api/motor-distance?id=1` 读取对应电机的换算；`POST /api/motor-distance` 以 `id`、`rotationDistance` 保存，0 表示清除。所有写操作必须显式触发；断线重连只读取状态。

执行时队列独占运动入口，普通网页命令和 UART 运动不能插队；查询和停止保留。运行中不能更改行程换算、调试策略或 Wi-Fi 设置。

## 显式等待

```text
move 1 90           # 发送后继续
move 1 90 await     # 等本次移动到位
home 2 2            # 发送后继续
home 2 2 await      # 等本次回零完成
```

`await` 不区分大小写，只能出现一次并放在 move/home 参数末尾、注释之前；可与单位和所有可选参数组合。它不是等待所有电机的屏障。其它指令使用 await 会在整段预检查时报错，不发送任何动作。

等待期间页面、反馈采集和取消仍可用。缺少反馈显示等待反馈，不自动超时、重发或停止；恢复后继续判断。明确拒绝或回零失败终止队列并报告行号。移动需接收应答、目标读回和两次新鲜到位静止反馈；回零需本次完成证据和两次新鲜静止反馈。旧缓存不能放行。

驱动协议没有动作序号，无法严格区分同一电机同类指令的迟到应答；需要严格串行时，应给该电机的每个 move/home 都加 await。队列结束只代表程序执行结束，未等待的动作仍可能运行。

## 同步组与螺旋动作

先在工作台右栏「查询预算与同步配置」显式保存同步参数，再按台架流程确认缓存隔离。初始同步配置全零，启动必定拒绝；不会猜测机械精度或驱动吞吐能力，也不会自动补使能。

```text
sync begin
move 1 360 deg 1 60 60 800
move 2 -180 deg 1 60 60 800
sync end
```

以上仅演示语法，不是已经验证的机械参数。每轴的速度和加减速度是上限：板端用最严格的归一化约束规划共同 s(t)，向下取整编码，再解析校验整个梯形/三角轨迹的比例与时间误差。过短行程、无法表示的参数、反馈预算不足均在发送前拒绝。

同步检查要求成员已使能、静止、无故障并有新鲜反馈。准备前读取原目标；缓存后同时要求接受应答及新目标读回，并核对位置未改变。新目标与原目标完全相同时拒绝，避免用旧目标给迟到 ACK 作错误佐证。驱动没有事务序号，`accepted` 表示收到同地址 CD 02，不声称能唯一关联 ACK；`ackAssociation` 明确其证据限制。只有所有成员通过，才发送一次 ID 0 的 `FF 66 6B`。

运行优先查询位置，故障状态低频读取，到达附近增加速度确认；每个成员取得两对独立的新鲜到位/静止样本后暂记完成，但持续查询其位置和速度，直到整组完成。若已到位成员再次偏离目标或运动，立即请求整组停止；整组完成时每个成员都必须仍有预算窗口内的新鲜到位/静止证据。不重复查询已确认目标。位置采样时间差、应答延迟预算、编码及到位容差进入误差区间；下界超容差或上界长期无法判定时请求整组停止。超出计划行程包络、成员故障、拒绝、准备/运动超时、反馈失效、CAN 不可用或暂停自动查询也会请求成员停止。不会自动重试、失能或续跑。

同步故障时每成员只自动请求一次 FE 停止，随后等待两对新鲜静止证据；用户执行取消或「全部停止」时，除成员停止请求外还发送广播回零中断和广播停止，覆盖此前可能仍在运行的非成员电机。停止确认超时仍显示未确认。`active=true` 在停止确认期间继续锁住新动作，即使队列已标记 cancelled。同步成员全部到位才产生运动完成；程序中还含未等待普通运动或原始帧时，整段队列仍只能报告发送结束。

螺旋示例（参数仍须按真实机构配置）：

```text
helix 1 2 3 2 1 1 -1 1 60 60 800 0.1
```

含义：旋转电机 1、直线电机 2，瓶盖 3 圈、导程 2 mm/瓶盖圈、旋转传动比 1 电机圈/瓶盖圈，方向分别 +1/-1，各轴限制 1 RPM、60/60 RPM/s、800 mA，轴向容差 0.1 mm。直线位移为 6 mm，角度使用电机 2 的板端 mm/rev 换算。角度量化误差从可用轴向容差中预先扣除；再取全局进度容差与螺旋容差的更严格者。一个 helix 占 4 个内部步骤，共享 64 步容量；网页只生成文本，不自行下发分轴命令。螺纹脱离不会自动识别，后续抬升单独编排。

### 配置与隔离 API

- `GET /api/sync-settings` 读取配置与最后确认的缓存隔离许可。
- `POST /api/sync-settings` 保存完整字段：`progressTolerance` (0,0.25]、`timeToleranceMs` 1..60000、`feedbackTimeoutMs` 200..30000、`prepareTimeoutMs` 1000..60000、`stopTimeoutMs` 500..30000、`responseBudgetMs` 1..5000、`completionTenths` 1..1000。除进度容差外均为整数；进度容差按百万分之一向下取整。应答预算还必须小于查询超时，最终许可按具体轨迹重新计算。
- `POST /api/sync-isolation` 只有显式填写 `cacheSemanticsVerified=1`、`allNodesIsolated=1`、`pendingRepliesDrained=1` 才记录人工确认；`revoke=1` 撤销。接口不发送清缓存帧、不检测或证明硬件已清理。确认只在 RAM 中，重启、原始帧、外部控制命令或同步异常使许可失效；成功同步可按已经人工验证的缓存消费语义继续下一组。
- 查询预算保存在 NVS `can-query/v1`，同步数值保存在 `sync-settings/v1`，不迁移旧配置。升级不要擦除整片 Flash；降级可忽略新增键。独立操作人与所有总线节点必须受控，不支持另一主站并发写入或热插拔后沿用旧隔离确认。

`GET /api/queue` 增加 `active`、`motionComplete`、`programHash`、`sync`。同步对象含阶段、错误、成员源行/发送时间/接受/目标确认/到位/停止证据、反馈预算、当前配合误差区间及最大可观测偏差。helix 同时报告 mm 单位区间。诊断里的 `raw_submitted` 只记录原始帧发送，不猜应答归属；外部同轴控制会使关联变为不确定。定位只在当前程序指纹匹配时跳转，避免把旧运行的行号套到新草稿。

这些接口沿用调试工作台的信任边界，仅用于受控局域网。人工许可不是安全认证，未验证缓存清理和非成员隔离前禁止同步实机验收。误差区间依赖已实测的延迟上界和驱动运动限制，不保证采样间隔内连续实际精度。

## 快速回零与全局使能（已有行为）

home await 收到本次接受应答后，若没有捕获到正在回零，允许在 1 秒启动宽限后使用新收到的“未回零、无失败”状态，随后以两次新鲜静止反馈完成等待；不强制要求观察到 07 → 03。仍在回零、失败、无应答或旧缓存不能放行。这是“已接受后停止且未报告失败”的判断，不保证机械零点正确。

顶部“全部使能”向总线广播 F3 使能，不启动运动；队列运行时不可插入。“全部失能”先取消队列及 UART 待执行操作、请求停止，再广播 F3 失能并清除软件运动状态。广播覆盖所有连接电机，发送成功不代表逐台确认，失能会释放保持力。
