# 电机执行诊断与低带宽同步开发记录

对象：motion 固件和设备工作台。阶段：普通直发诊断、统一查询预算、多轴同步首版。
本文记录本次开发契约、证据和未完成验收；现有功能说明仍见 motor-queue.md。

## 开发计划与验收证据

1. 普通队列：真实 Queue → MotorControl → X42sProtocol → TWAI 边界双电机测试；运行/轮次/行/地址/功能码诊断。被动观察不产生查询，不改变普通直发时序。
2. 查询：唯一板端调度器合并 ID+字段需求；全局速率、间隔、在途、超时冷却、无积欠突发；页面只读缓存；配置持久化和 TX/RX 质量统计。
3. 同步：2–8 轴语法、共同梯形/三角轨迹、编码误差校验、helix 板端换算；检查、缓存、确认、单次广播、监测、完成；异常整组请求停止并保留使能。
4. UI/API：兼容旧字段，增加有界诊断、成员和阶段；顶部持久异常、定位和详情；表单、折叠说明、重建嵌入页面。
5. 验证：主机回归、真实编码测试、调度/规划/状态机测试、浏览器、双板构建及内存/栈检查。最后分阶段实测，不以主机测试替代设备验收。

## 已确认的初始证据

- 基线 4d179ee，桌面 main 干净；开发 worktree /private/tmp/babytech-firmware-motion，分支 codex/motor-sync-budget。
- 普通 move 已走 queueSendLogical → sendRawLogical；CD 参数为相对当前位置、sync=0，分三包。未发现只允许一个电机发送的队列锁。
- 现有 command-queue 测试替换 X42sProtocol，不能单独证明真实发送路径。
- RX 的 nodeOfInterest 过滤会忽略未选中、非 await 普通队列电机的 ACK。这是确定的诊断缺失，不足以证明是机械不动作的根因。
- serviceQueries 每次除基础字段外还可能附加 home/target 查询；await 另以 50ms 间隔发查询。没有统一在途/总预算。
- 手册确认 sync=1 缓存、FF 广播启动；未给出足以证明未知/非成员缓存已清除的本机实测证据。

## 契约及约束

- 保留 state/runId/step/total/iteration/repeat/line/action/message/raw。新增数据只增加字段，普通 done 的 UI 含义始终为发送结束。
- 诊断有界，滚动淘汰必须报告计数；跨轮次/运行同轴同功能码存在无法排除的迟到应答，不能靠时间窗伪造归属。
- ACK 02 表示驱动接受；9F 为驱动报告完成，不单独等同机械完成；普通动作不因诊断异常自动停止或重试。
- 查询预算是未实测的配置，不是驱动吞吐承诺。同步前必须验证采样可判定性；不通过无限提高轮询解决丢反馈。
- 不自动使能、不自动清缓存、不用失能代替停止；重启/未知原始命令/部分缓存失败后缓存隔离必须保持未知，直到有可靠证据。

## 尚待实测

双 move：逐台、连续、交换顺序、显式短 wait 对照，记录每轮源行与 TX/RX、机械结果。
独立负载台架：单位动作帧数、应答延迟/缺失、RX missed/overrun，确定最低必要查询频率。
缓存隔离：停止是否清缓存、覆盖行为、非成员遗留缓存、板端重启后广播行为。
最后空载同步、低速拧盖，记录最大可观测配合误差；不能声称采样间隔内连续实际精度。

硬件、驱动版本、设备地址和机械行程尚未在本次任务中验证；当前不得宣称双 move 实机修复或同步实机验收通过。

## 当前软件实现（2026-09-23）

- 普通动作被动诊断、未选中电机 ACK、有界 64 条事件和首个异常；原始帧只记发送。同轴重复或外部控制使 ACK 关联不确定，既不重试也不追加停止。顶部异常、运行指纹核对后定位、可展开详情均已接入。
- Controller/Await/Page/Sync 共用 CanQueryScheduler。ID+字段合并、在途上限、速率与间隔、超时冷却、无积欠突发；同步独占查询需求，普通/停止操作优先，可选查询最后发送。配置版本化保存到 NVS。
- sync/helix 完整解析、共同进度规划、解析求取整后的轨迹误差极值、板端几何换算、反馈可判定性预检、独立同步状态机及停止证据跟踪。缓存后目标必须与准备前目标不同，并匹配本次相对运动；ACK 没有事务序号，不夸大其归属能力。
- 重启、原始/外部控制或异常使缓存许可失效；恢复必须人工确认已完成台架检查。本版没有可证明的自动清缓存算法，不会偷偷下发试探性广播。所有成员仍需显式使能。
- 网页提供 helix 文本生成、同步阶段/成员/误差区间、查询统计、预算和同步配置表单；只读和编辑不产生 POST，保存必须点击。停止确认未结束时不解锁新动作。
- 混合程序含未等待普通运动时，后面的同步组即使完成，整段程序仍只称发送结束。机械完成与发送结束、停止请求与静止证据分开。

## 必须完成的分阶段实机验收

当前未识别串口、未确认驱动版本、未烧录、未发真实电机指令。以下每阶段都需设备负责人授权及记录，不能以人工许可开关代替证据。

1. **双 move 定位**：空载、确认行程/急停/地址/供电及线序。分别执行两条 move，再连续执行、交换顺序、插入显式短 wait 对照。记录程序/运行编号、TX/RX、ACK 时间与机械结果，比较每轮命令和反馈数量。只发现 ACK 被过滤不是“电机不动”的实机根因，未复现不能宣布修复。
2. **独立查询台架**：不拧盖、不跑同步负载。在同一安全动作/静止条件下，用显式保存的预算逐档测延迟分布/最大值、未应答、TX failed、RX missed/overrun 和动作帧数；比较一个/多个浏览器、不同刷新频率，合计查询不得突破一份预算。离线成员不能长期占满槽；原始帧和停止优先。按测量留余量填写 responseBudgetMs，不自动探测上限。
3. **缓存语义与隔离**：空载隔离台架，逐项验证缓存覆盖、33 是否在触发前返回待执行目标、停止是否清缓存、FF 后是否消费一次、非成员遗留缓存、控制板重启而驱动未断电等情形。部分准备失败后必须先用已证实的方法清理所有可能遗留节点，排空迟到回复；验证失败就保留禁用，不能通过勾选绕过。确认连接的所有节点受控，禁止其它主站并发命令。
4. **空载同步**：先低速双轴异向及不同比例，再扩大成员数与短行程。记录两轴目标、参数取整误差、最大可观测配合误差、回复质量和单位动作帧数；分别注入缓存拒绝、成员断线、停止未确认，确认不会重复触发、失能或继续下一步。
5. **低速拧盖**：最后单独按实际导程/传动比/方向/电流上限/轴向容差运行。不要同时做吞吐极限测试；脱扣和后续抬升由人工判断及显式编排。若需要连续实际精度证明，增加独立测量，不能拿低频反馈区间替代。

升级仅需 Motion 固件（含嵌入网页）；Brain 已做兼容构建但代码未改，不要求重刷。无数据库迁移；保留现有 Wi-Fi、标定及 rotation distance NVS，升级前记录配置和旧固件备份，不执行整片擦除。新设置使用独立 NVS 键，回退旧固件不会迁移或删除旧配置。
